# sentryrg.com

Next.js rebuild of the Sentry Roofing marketing site, from the Claude Design
prototype in `reference/prototype`.

## Deploy

Netlify project **sentryrg** (team Max Capacity).
Site ID `c103fe2c-3595-45e6-a1a6-453b0acc49f9` · https://sentryrg.netlify.app

Netlify's Next.js runtime is auto-detected; `next/image` routes through
Netlify Image CDN. `npm run build` is the build command.

## Commands

| Command | Does |
| --- | --- |
| `npm run dev` | Dev server |
| `npm run build` | Production build |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run optimize:assets` | Rebuild `public/assets` from `reference/assets-src` |

## Assets

Originals live in Google Drive and are **not** in git (`reference/assets-src`
is gitignored, ~107MB). Only the optimized derivatives in `public/assets` are
committed.

`npm run optimize:assets` needs **ffmpeg** and does three things:

1. Images to WebP, long edge capped at 1920px. Several originals were far
   oversized for web (`svc-storm.jpg` was a 24MP camera frame).
2. The hero video transcoded from HEVC to H.264 + VP9. The client's original
   is HEVC/H.265, which does not play in Chrome or Firefox, so shipping it
   as-is leaves the hero blank for most visitors. It is also re-encoded at a
   sane bitrate, stripped of its unused audio track, and faststarted so
   playback can begin before the file finishes downloading.
3. `build-logo.mjs` reconstructs a transparent logo (see below).

Only assets the prototype actually references are shipped. The list is
generated by `node scripts/scan-asset-usage.mjs` into `reference/assets-used.txt`;
the handoff carried 69 assets and the pages use 47.

## Known issues to resolve with the client

- **Logo.** The handoff contained no usable transparent logo, so
  `scripts/build-logo.mjs` reconstructs one from `logo-light.png` by flood
  filling its black plate. It works, but a real transparent PNG or SVG from
  the client should replace it, at which point delete that script. There is
  also no dark-on-light logo for light-ground sections.
- **`welcome-crew.jpg`** (About page crew photo) is still missing. It exceeds
  what the Drive connector can transfer.
